# docgen 파일 안내

`docgen/` 폴더에 있는 파일이 각각 무엇이고, 어떤 일을 할 때 무엇을 열면 되는지 정리했다.
경로는 전부 `docgen/` 기준이다. 설계 이유와 조문 근거는 한 단계 위 폴더의 `법정-문서-대시보드-통합설계.html` 에 있다.

## 표시

| 표시 | 뜻 |
|---|---|
| ❗ | **꼭 확인 · 수정** — 실제로 쓰기 전에 사람이 확인하고 고쳐야 한다 |
| ✏️ | **고쳐도 됨** — 수치 튜닝이나 문구 조정. 안 고쳐도 돌아간다 |
| 🎬 | **시연용** — 시연하려고 만든 샘플(Claude가 만든 것). 실제로 쓸 때는 진짜 데이터로 바꾸거나 뺀다 |
| ⚙️ | **자동 생성** — 프로그램이 실행하면서 만든다. 손으로 고치지 않는다 |
| (표시 없음) | 코드 · 안내 문서. 기능을 바꿀 때만 연다 |

## 1. 한눈에

```
docgen/
├─ app.py                        화면 — python app.py (사이드바 틀에 문서 자동화 묶음만)
├─ run_demo.py                 🎬 화면 없이 문서 전부 만들기
├─ README.md                      실행 방법 · 계산 규칙 요약
├─ 파일안내.md                    이 문서
├─ requirements.txt               설치할 패키지 목록
├─ .env.example                ❗ AI 설정 · 샘플 데이터 켜고 끄기 틀 → .env 로 복사해서 키를 넣는다
├─ pyrightconfig.json             편집기(VS Code) 설정 — 프로그램 동작과 무관
│
├─ config/                        설정 — 사람이 고치는 곳은 대부분 여기
│  ├─ scales.json              ✏️ 가능성 · 중대성 환산표, 수시평가 기준, 조치 기한
│  ├─ obligations.json         ❗ 법정 의무 11개 · 주기 · 기한 · 근거 조문 · 서류 보존
│  ├─ documents.json           ❗ 문서 7종의 법적 근거 · 보존 기간
│  ├─ legal_articles.json      ❗ AI가 고를 수 있는 조문 17개 (원문 대조 못 한 2개)
│  ├─ staff.json               ❗ 이행 처리 담당자 — 실제 담당자로 채운다 (샘플 7명은 예시 폴더에)
│  ├─ site_profile.json        ❗ 사업장 정보 · 마지막 실시일 · 사고 (시연 날짜 · 샘플 사고는 예시 폴더에)
│  ├─ rulesets.json            🎬 규칙셋 — 관제 쪽 실제 파일이 생기면 교체
│  ├─ piping.json              🎬 배관 계통도 — Z8 배소로 3계통
│  └─ incident_cases.json         쓰지 않음 (사고 레이더 화면용으로 남겨 둠)
│
├─ safety_docs/                   기능 코드
│  ├─ config.py                ❗ 설정 · 기록 읽기쓰기. 실제 관제 DB 연결은 여기서
│  ├─ risk.py                     위험도 계산 — 숫자는 전부 여기서 나온다
│  ├─ assessment.py            ✏️ 위험성평가 초안 · 서명 · 확정 (AI 지시문 포함)
│  ├─ corrective.py            ✏️ 시정지시서 (AI 지시문 포함)
│  ├─ ptw.py                   ✏️ 작업허가서 점검 (AI 지시문 포함)
│  ├─ accident.py              ✏️ 산업재해조사표 (AI 지시문 포함)
│  ├─ compliance.py               의무 이행 관리
│  ├─ voice.py                    안전소통
│  ├─ home.py                     홈
│  ├─ archive.py                  기록
│  ├─ export.py                   엑셀 · 워드 서식
│  ├─ handoff.py                  관제 인계 — 관제가 넘긴 감지 내역 받기 · 보고서 만들기 · 허가서 등록
│  ├─ ui.py                    ✏️ 문서 자동화 다섯 화면 (Gradio) — 화면 배치 · 문구
│  ├─ shell.py                 ✏️ 한 프로그램의 틀 — 사이드바 메뉴 묶음 · 화면 전환 · 색 · 글꼴
│  ├─ llm.py                      Claude / OpenAI / mock 연결 · 캐시
│  ├─ radar.py                    쓰지 않음 (사고 레이더 화면을 뺐다)
│  └─ __init__.py                 묶음 표시 + 원칙 요약
│
├─ mock/                       🎬 API 키 없이 돌릴 때 쓰는, 미리 써 둔 AI 답
│                                 샘플 데이터는 여기 없다 → 폴더 맨 위 예시데이터_삭제가능/문서자동화/ (지워도 된다)
│
├─ records/                    ⚙️ 서명 · 발행 · 이행 처리 · 관제 인계 기록 (추가 전용)
├─ outputs/                    ⚙️ 만든 엑셀 · 워드 문서
├─ cache/                      ⚙️ AI 답 저장 (실제 API로 돌렸을 때만 생긴다)
└─ safety_docs/__pycache__/    ⚙️ 파이썬 실행 캐시 — 지워도 된다
```

## 2. 이럴 때 이걸 연다

| 하려는 일 | 열 파일 · 할 일 | 참고 |
|---|---|---|
| 화면 켜기 | 폴더 맨 위 `app.py` 실행 | `python app.py` → http://127.0.0.1:7860 (관제 여섯 + 문서 자동화 다섯 메뉴). 문서 자동화만은 `docgen/app.py` |
| 관제 엔진 결과를 넘겨 보기 | 화면의 안전 문서 › 관제 인계 › ‘관제 엔진 결과 파일로 넘기기’ | monitor_engine `outputs/…/events.jsonl` 을 올리고 그 폴더를 적는다. 관제 화면의 ‘문서 자동화로 넘기기’ 버튼이 같은 일을 한다 |
| 관제 화면과 잇는 법 | 폴더 맨 위 `app.py` · `control/pages.py` | README ‘한 프로그램 — 관제와 합친 진입점’ — `ctx.refs` 의 open_handoff · open_tab |
| 샘플 이벤트 · 샘플 허가서 끄기 | `.env` → `DOCGEN_SAMPLE_DATA=off` | 관제에서 넘어온 기록만으로 돈다. 엔진 결과를 넘겨 시험할 때 샘플과 겹쳐 세지 않으려면 끈다 |
| 화면 없이 문서를 한꺼번에 만들기 | `run_demo.py` 실행 | 결과는 `outputs/` |
| 처음 설치 | `requirements.txt` | `pip install -r requirements.txt` |
| 실제 AI(Claude · OpenAI)로 문장 쓰기 | `.env` | `.env.example` 을 `.env` 로 복사하고 키를 넣는다. 화면 오른쪽 위 ‘문장 생성’ 드롭다운으로도 바꾼다 |
| 발표장에서 네트워크 없이 같은 결과 | `python run_demo.py --provider claude` 를 시연 전날 한 번 | 답이 `cache/` 에 남아 다음부터는 API를 부르지 않는다 |
| 가능성 · 중대성 · 등급 기준 바꾸기 | `config/scales.json` | `likelihood_steps` · `severity_by_violation` · `grades` |
| 수시평가 제안 기준(위험도 12) | `config/scales.json` → `adhoc_review` | 통합 문서의 피드백 절대 기준과 같은 값이라 같이 바꾼다 |
| 시정지시서 조치 기한(일수) | `config/scales.json` → `correction_deadline_days` | 법정 기한이 아니라 내부 기준 |
| 법정 의무 · 주기 · 알림 시점 | `config/obligations.json` | 알림은 `alert_days` = 기한 30 · 7 · 1일 전 |
| 서류 보존 기간 | `config/documents.json` (문서별) · `config/obligations.json` 의 `retention` (의무별) | 기록 화면의 보존 기한이 여기서 계산된다 |
| 담당자 추가 · 변경 | `config/staff.json` | 의무 이행 관리 탭을 다시 열면 목록이 새로 읽힌다 |
| 사업장 규모 · 업종 · 마지막 실시일 | `config/site_profile.json` | 화면에서 바꾼 업종 · 인원은 저장되지 않는다(보기용) |
| 시연 날짜(2026-10-12) 끄기 | `config/site_profile.json` → `demo_today` 줄 삭제 | 지우면 진짜 오늘 날짜로 돈다 |
| AI가 쓰는 문장의 말투 · 금지 사항 | `safety_docs/assessment.py` · `corrective.py` · `ptw.py` · `accident.py` 위쪽의 `SYSTEM = """..."""` | 숫자는 AI가 못 바꾸게 되어 있으니 문장 지시만 고친다 |
| AI가 인용할 수 있는 조문 | `config/legal_articles.json` | 목록에 없는 조문은 결과에서 자동으로 빠진다 |
| 격리 기준값(퍼지 시간 · LEL) | `config/rulesets.json` → `isolation` | R1 · R2 · R4 가 쓰는 값 |
| 관제 엔진 위반 이름의 중대성 | `config/scales.json` → `severity_by_violation` | 엔진 rules.json 의 `violation` 과 글자까지 같아야 한다. 없는 이름은 `severity_default`(2) |
| 엑셀 · 워드 서식 | `safety_docs/export.py` | |
| 화면 배치 · 버튼 · 안내 문구 | `safety_docs/ui.py` 아래쪽 `build(ctx)` 부분 | 화면마다 `with ctx.page("id"):` |
| 사이드바 · 화면 색 · 글꼴 | `safety_docs/shell.py` 의 `CSS` · `THEME` | 관제 화면과 같이 쓴다 |
| 만든 문서 찾기 | `outputs/` | 파일 이름 규칙은 4장 |
| 누가 언제 서명 · 처리했는지 | 화면의 ‘기록’ 탭 | 원본은 `records/` |
| 실제 관제 DB(MySQL)에 연결 | `safety_docs/config.py` → `load_events()` | 같은 필드로 읽게 한 곳만 바꾸면 된다 |
| 시연을 처음 상태로 되돌리기 | 6장 | |

## 3. 파일별 설명

### 3-1. 바로 아래 파일

| 파일 | 목적 | 언제 여나 |
|---|---|---|
| `app.py` | 사이드바 틀(`shell.py`)에 문서 자동화 묶음(`ui.py`) 하나를 넣어 띄우는 몇 줄. 관제 화면이 붙으면 진입점은 폴더 맨 위 `app.py` 로 옮긴다 | 켤 때 실행 |
| `run_demo.py` 🎬 | 화면 없이 작업허가서 점검 → 시정지시서 → 위험성평가 초안 → 산업재해조사표를 차례로 만들고, 의무 일정 · 홈 요약을 글자로 찍는다 | 화면 없이 결과를 확인할 때, 시연 전 AI 답을 캐시에 받아 둘 때 |
| `README.md` | 실행 방법 · 화면 · 문서별 근거와 보존 기간 · 계산 규칙 · 두 단계 서명 · 이행 처리 요약 | 처음 볼 때 |
| `파일안내.md` | 이 문서 | 파일을 찾을 때 |
| `requirements.txt` | 설치할 파이썬 패키지 목록 | 새 PC에 설치할 때 |
| `.env.example` ❗ | AI 설정 틀. `LLM_PROVIDER`(mock · claude · openai), API 키, 모델 이름 | `.env` 로 복사해 키를 넣는다. **`.env` 는 공유하거나 깃에 올리지 않는다** |
| `pyrightconfig.json` | VS Code가 폴더 전체를 검사하게 하는 편집기 설정 | 건드릴 일 없음 |

### 3-2. `config/` — 설정

| 파일 | 담는 것 | 사람이 할 일 |
|---|---|---|
| `config/scales.json` ✏️ | 최근 90일 창 · 가능성 구간(0건 1 ~ 11건 이상 5) · 하한(최고 경보 4, 사고 5) · 위반 유형별 중대성 · 등급 · 수시평가 기준 · 개선 효과 최소 14일 · 조치 기한 | 전부 **초기값**이다. 팀에서 합의하면 고친다. 통합 문서와 값이 같게 맞춰 두었으니 한쪽을 바꾸면 다른 쪽도 고친다 |
| `config/obligations.json` ❗ | 법정 의무 11개 — 달력형 6(정기 위험성평가 · 중처법 반기 점검 · 산보위 · 작업환경측정 · 근로자 교육 · 관리감독자 교육), 사건형 5(산업재해조사표 · 중대재해 보고 · 수시평가 · 시정지시 조치 · 제보 조치). 대상 조건 · 주기 · 기한 · 근거 조문 · 서류 보존 · 구분 | 1차 금속 제조업 기준으로 적었다. **실제 사업장에 쓰기 전에 안전관리자가 주기 · 기한 · 대상 조건을 확인**한다 |
| `config/documents.json` ❗ | 문서 7종(위험성평가표 · 시정지시서 · 작업허가서 점검 · 산업재해조사표 · 안전소통 기록 · 의무 이행 기록 · 규칙셋 개정 이력)의 근거와 보존 기간 · 기산일 | 보존 기간을 확인한다. 법정 기간이 없는 것(작업허가서 점검)은 중처법 이행 증빙으로 5년을 잡아 둔 것 |
| `config/legal_articles.json` ❗ | AI가 문서 초안에서 고를 수 있는 조문 17개 | **`verified: false` 2개(안전보건규칙 제240조 · 제278조)는 세부 호를 원문과 대조하지 못했다.** 국가법령정보센터에서 확인하고 `true` 로 바꾼다 |
| `config/staff.json` 🎬❗ | 이행 처리 담당자 — 이름 · 부서 · 직책 | **이름 7명은 샘플**이다. 실제 사람으로 바꾼다. `id` 는 기록에 남으므로 한 번 쓴 것은 바꾸지 않는다. 목록에 없는 이름으로 남은 옛 기록은 부서 · 직책이 ‘-’로 나오는데, 같은 이름을 추가하면 채워진다 |
| `config/site_profile.json` 🎬❗ | 샘플 사업장(1차 금속 · 320명 · 유해인자 노출), `demo_today`(2026-10-12), `last_done`(의무별 도입 전 마지막 실시일), `accidents`(사고 4건) | **실제 운영 전에 사업장 정보와 `last_done` 날짜를 실제 값으로**, `demo_today` 는 지운다. 사고 4건은 시연용 |
| `config/rulesets.json` 🎬 | 샘플 규칙셋 — 모드 3개(평상시 · 대수리 사전 작업 · 산세 구역 화기), 구역 이름, `isolation`(R1 · R2 · R4 기준값), `rule_changes`(R1~R4) | 관제 쪽 실제 `rulesets.json` 이 생기면 그 내용과 맞춘다. 격리 기준값(퍼지 30분 · LEL 5% 등)은 초기값 ✏️ |
| `config/piping.json` 🎬 | 배관 계통도 — Z8 배소로의 FG-01 주 연료가스 · CA-01 연소 공기 · FG-02 파일럿 버너, 인접 구역 | 시연 시나리오에 맞춘 것. 실제로는 설비 도면 DB에서 읽는다 |
| `config/incident_cases.json` | 사고 레이더용 공개 사고 사례 | 지금은 쓰지 않는다. 사고 레이더를 다시 붙일 때만 |

### 3-3. `safety_docs/` — 기능 코드

| 파일 | 하는 일 | AI 사용 | 언제 여나 |
|---|---|---|---|
| `safety_docs/config.py` ❗ | 설정 · 기록 파일 읽기쓰기, 이벤트 읽기(`load_events`), 시연 시계(`now`), 날짜 양식 맞추기(`parse_date`), 담당자 목록 | 없음 | **관제 DB에 연결할 때** — `load_events()` 를 MySQL events 테이블 읽기로 바꾼다(아래쪽 주석에 예시) |
| `safety_docs/risk.py` | 이벤트 집계 → 가능성 · 중대성 · 위험도 · 등급, 수시평가 제안, 개선 효과 실측, 조치 기한 | 없음 | 계산 방식 자체를 바꿀 때. 수치만 바꿀 거면 `config/scales.json` |
| `safety_docs/assessment.py` ✏️ | 위험성평가 초안(AI 문장) → 관리자 서명 → 근로자 대표 확인 · 반려 → 규칙셋 버전 올리기 | 문장만 | 위쪽 `SYSTEM` 에서 AI 지시문을 고칠 때 |

### `cache/` · `__pycache__/`

- `cache/` — 실제 AI 답을 저장한다. 지시문과 입력이 같으면 다시 부르지 않고, 둘 중 하나라도 바뀌면 새로 부른다. 같은 입력인데 답을 새로 받고 싶을 때만 지운다.
- `safety_docs/__pycache__/` — 파이썬이 알아서 만드는 실행 캐시. 지워도 된다.

## 7. 시연을 처음 상태로 되돌리기

1. 화면(`app.py`)을 끈다.
2. `records/` 폴더 이름을 바꿔 둔다(예: `records_0930`). **지우지 말고 옮겨 두면 되돌릴 수 있다.** `records/` 가 없어도 화면은 예시 데이터로 정상적으로 뜬다. 관제 기록은 폴더 맨 위 `control/records/` 도 같이 옮긴다.
3. `outputs/` 안의 문서는 지워도 된다(다시 만들어진다).
4. AI 답을 새로 받고 싶으면 `cache/` 를 지운다.
5. `python app.py` 로 다시 켠다.
