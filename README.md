# 트리거형 안전관제 — 관제 대시보드 + 문서 자동화 (한 프로그램)

작업 모드가 켜진 순간에만 규칙을 강하게 거는 관제 시스템과, 그 기록으로 법정 문서 초안을 만드는 문서 자동화를
**한 프로그램**으로 묶었다. 화면은 화면 시안(`실사용 자료/안전관제_대시보드.html`)의 HTML · CSS 그대로이고,
시안에 박혀 있던 예시 값 자리만 실제 기능의 결과로 채운다. 왼쪽 사이드바에 두 묶음이 있고, 경보는 팝업으로 뜬다(실시간 관제에서는 오른쪽 아래, 다른 화면에서는 오른쪽 위).
상태 색 · 표현 체계(10/6 확정)는 `자료/대시보드-통합설계.html` 12장 — 단계 색은 최고 경보 · 경보 · 주의 · 정상 · 무음 기록에만 쓰고 아이콘 · 글자를 늘 같이 쓴다.

| 묶음 | 화면 | 코드 |
| --- | --- | --- |
| 관제 | 실시간 관제 · 격리 목록 대조 · 이벤트 로그 · 재생 비교 · 피드백 · 조정 로그 · 히트맵 · 통계 | `control/` |
| 문서 자동화 | 홈 · 의무 이행 관리 · 안전 문서 · 안전소통 · 기록 | `docgen/` |

판정은 `monitor_engine/`(3축 판정 · 모드 · 작업 전 게이트 · 영상 탐지)이 하고, 사업장마다 다른 것(구역 · 신호 · 판정표 ·
개정안 · 카메라 · 시나리오)은 **사업장 패키지**에서 읽는다.

기능 확인용 예시 데이터(예시 사업장 패키지 · 샘플 이벤트 · 허가서 · 제보 · 시연 날짜 …)는 전부
`예시데이터_삭제가능/` 한 폴더에 있다. 실제 데이터를 받으면 그 폴더를 지우고 넣는다 — `예시데이터_삭제가능/README.md`.

## 켜기

```
pip install -r requirements.txt
python app.py                  # 브라우저가 열린다 → http://127.0.0.1:7860
python app.py --no-browser --port 7870
python app_gradio.py           # 예비 — 같은 기능을 Gradio 부품으로 그린 예전 화면
```

화면(`web/`)은 기능 코드를 부르기만 한다. 판정 · 계산 · 기록은 전부 `control/` · `monitor_engine/` · `docgen/safety_docs/` 에 있어서,
Gradio 화면(`app_gradio.py`)으로 바꿔도 같은 기능이 돈다. HTML 화면에만 있는 것은 경보 팝업 · 작업중지 지시 버튼 정도다.

처음에는 문장 생성이 `mock`(API 키 없이 미리 써 둔 답)이다. Claude · OpenAI 는 `docgen/.env` 에 키를 넣고 사이드바 아래 '문장 생성'에서 고른다.

## 시연 순서 (5분)

1. **실시간 관제** › 맨 위 얇은 시연 줄의 **시연 설정** — 스케줄 `B · 연료가스 배관 맹판 격리`, 규칙셋, 영상 장면을 고르고 속도(60×) → **새 세션 시작**.
   - 규칙셋 `문서 자동화 확정분` = 위험성평가에서 확정된 개정안만 켠다(실제 운영과 같다). `개정안 전부` 로 두면 08:05 격리 목록 누락이 작업 전 게이트로 막힌다.
   - 영상 장면 `그라인더 불티` 를 고르면 09:15 에 영상 탐지(불꽃 → 점화원)가 붙고 대표 프레임 · 클립이 남는다.
   - **+ 영상 올리기 · 구역 설정** — 영상(mp4)을 올리면 첫 프레임이 뜨고, 그 위에 구역을 마우스로 찍는다(종류: 위험구역 상시 · 위험구역 작업 중 · 작업 구역 · 출입 제한 + 관리자가 더한 종류).
     저장하면 영상 장면 목록에 들어가고, 그 장면이 도는 동안 카메라 기본 구역 대신 그 구역으로 판정한다. 있는 장면은 **고른 장면 구역 고치기**로 점을 옮긴다.
     판정은 구역 이름이 아니라 종류로 걸리므로 규칙 · 판정표는 고치지 않아도 된다. 위험구역은 불꽃이 실제로 나는 자리를 덮게 그린다.
   - **저장하고 관제에서 재생** · **⏭ 고른 장면 바로 재생** — 장면 시각(예: 09:15)까지 스케줄을 1분씩 빨리 감고(사이 신호는 다 넣는다) 영상을 바로 튼다.
     장면만 고르고 시작하면 그 시각까지는 카메라 칸에 영상 첫 프레임 + 구역이 뜨고 '몇 분 남음'이 보인다.
   - 시연 줄의 알약이 지금 상태다 — `○ 시작 전` · `● 시연 중 10×` · `● 영상 재생 중 0:07 / 0:19` · `⏸ 멈춤`, 옆이 시연 시각.
   - **종류 관리**(구역 추가 줄 끝) — 통로 · 설비 위치처럼 판정에 안 쓰는 종류를 관리자가 더하고 지운다(패키지 `zone_types.json`). 화면 표시와 사람 위치 기록용이고, 판정에 쓰려면 rules.json 의 polygons 에 영문 키를 적는다.
   - **+ 카메라** (카메라 칸 옆) — 카메라 한 대를 더한다(패키지 `cameras/<ID>.json`, 기본 구역 없이). 그 카메라를 쓰는 장면은 화면에서 그린 구역으로 판정한다.
   - 현장 입력(버튼 · 신호 넣기)은 화면 맨 아래 접는 칸 **현장 입력**에 있다 — 시연 줄의 **현장 입력 ↓**로 바로 열린다. 엔진 메모도 그 옆 접는 칸.
   - 현장 입력 버튼 · 입력창으로 잘못 넣으면 **↶ 되돌리기** (시연 줄에도 같은 버튼이 뜬다) — 판정 상태를 그 입력 직전으로 돌린다. 관제 기록은 추가 전용이라 지우지 않고, 그 뒤 기록이 있으면 '입력 취소' 기록을 덧붙인다.
2. 경보가 뜨면 팝업이 뜨고(작업 전 차단 · 사고 · 주의 · 경보 · 최고 경보 — 실시간 관제에서는 오른쪽 아래), 구역 · 카메라 · 3축 신호판 → 현재 판정 · 판정표(몇 번 줄) · 작업허가서가 그 구역으로 따라간다.
   팝업의 **작업중지 지시**는 지시 시각을 관제 기록으로 남긴다(방송 설비 연동은 아직 없다).
3. **문서 자동화로 넘기기** → 문서 자동화 › 안전 문서 › 관제 인계가 열린다 → 시정지시서 초안 만들기.
4. **이벤트 로그**에서 기록을 골라 프레임 · 판정 근거를 보고, 오탐 표시 · 시정지시서 초안으로 보낸다.
   검색창에 낱말을 띄어 쓰면(예: `Z8 점화원`) 모두 들어간 기록만 남는다 — 판정 근거 · 대응 · 규칙셋 같은 표에 안 보이는 칸과 화면 이름(작업 전 차단 · 무음 · 오탐 · 강화)까지 찾는다.
   종류 · 단계는 바로, 위반 유형 · 규칙셋 · 표시 · 출처는 **상세 필터**에서 고른다. 조건을 바꾸면 **적용**(검색창에서는 Enter)을 눌러야 표와 '보이는 경보 이상 넘기기'에 반영된다.
5. **격리 목록 대조** › + 작업허가서 등록 → 예시 채우기 → 등록 → 누락이 작업 전 게이트로 잡히고, 맹판 · 가스 측정 · 퍼지를 단계 입력.
6. **피드백 · 조정 로그**에서 자동 조정(기한부 강화)을 보고 되돌리기 · 승격 · 방식 전환(자동 ↔ 승인형).
   긴 루프는 변경안(R1 …)마다 다섯 단계(제안 → 관리자 서명 → 근로자 확인 → 위험성평가 확정 → 규칙셋 반영)로 보이고,
   근로자 확인 전이면 **반려**로 변경안 하나만 돌려보낸다(확정할 때 그 변경안만 빠진다 · 반려 취소 가능).
   아래 조정 로그는 상태가 바뀔 때마다 한 줄이고 긴 루프 기록도 같이 보인다 — 기간 · 구역 · 루프 유형 · 결과 · 처리자 · 검색으로 거르고 CSV로 내려받는다.
7. **재생 비교**에서 개정 전 · 후를 나란히 돌려 기대 결과와 맞춘다.

## 기록 — 전부 추가만 되고 지워지지 않는다

| 파일 | 내용 |
| --- | --- |
| `control/records/live/<세션>/events.jsonl` | 관제 기록 (감지 · 게이트 · 사고 · 참고). `frames/` 대표 프레임, `clips/` 전후 클립, `modes.jsonl` 모드 켜짐 시각, `session.json` 세션 정보 |
| `control/records/adjustments.jsonl` | 조정 로그 — 자동 조정 · 승인 · 되돌림 · 만료 · 승격 · 방식 전환 (사유 · 처리자) |
| `control/records/isolation_steps.jsonl` | 맹판 설치 · 가스 측정 · 퍼지 단계 입력 |
| `control/records/replay/` | 재생 비교 결과 (관제 기록에는 넣지 않는다) |
| `docgen/records/monitor_events.jsonl` · `handoffs.jsonl` | 관제 → 문서 자동화 인계 (자동 인계 + 버튼 인계) |
| `docgen/records/ptw/` | 격리 목록 대조에서 등록한 작업허가서 · 격리 목록 |
| `docgen/records/false_positive_marks.jsonl` | 오탐 표시 (표시자 · 사유) |
| `docgen/records/rule_rejections.jsonl` | 규칙 변경안 단위 반려 · 반려 취소 (평가 번호 · 변경안 · 처리자 · 역할 · 사유) — 피드백 · 조정 로그(긴 루프)에서 누른다 |

## 예시 데이터 · 아직 없는 것

- 예시 데이터는 `예시데이터_삭제가능/` 에만 있다. 지우면 관제는 **실제 사업장 패키지**(`monitor_engine/packages/<이름>/` + `control/config.json` 의 `package`)가 있어야 켜지고,
  문서 자동화는 샘플 없이 `docgen/records/` · `docgen/config/` 만으로 돈다. 지우지 않고 샘플만 끄려면 `docgen/.env` 에 `DOCGEN_SAMPLE_DATA=off`.
- 영상: 예시 패키지의 `videos/test_synthetic.mp4` 는 합성 영상이다. AI 생성 영상은 화면의 **영상 올리기 · 구역 설정**으로 올린다
  (사업장 패키지 `videos/` 에 저장되고, 구역은 그 시나리오 `scenario.json` 의 `scenes[].polygons` 에 들어간다). 장면에 `polygons` 가 없으면 `cameras/*.json` 의 기본 구역을 쓴다.
- 사람 탐지는 `ultralytics`(YOLO) 가 설치돼 있어야 돈다. 없으면 사람 없이(불꽃 · 신호만) 돌고 상태 줄에 이유가 보인다.
- 불꽃(색 방식)은 노랑 · 주황 작업복 · 안전모를 불티로 잡지 않게 사람 박스 안 · 채도 높은 색 면 · 따뜻한 색에서 떨어진 흰빛을 빼고 본다(`detect.json` flame.color 의 skip_person · solid_* · white_near_warm …).
  사람 박스를 빼는 단계가 가장 크게 듣는다 — 사람 탐지가 없으면 흰 안전모 · 맨손 같은 것이 후보로 남을 수 있다.
- 안전모 탐지 모델은 아직 없다 — 통계는 착용률 대신 안전모 미착용 기록 건수를 부서별로 보인다. `monitor_engine/config/detect.json` 의 `extra` 에 `no_helmet` 모델을 붙이면 착용률로 바뀐다.
- '모드가 켜졌을 때 vs 평상시'는 실시간 세션이 남긴 모드 시간으로만 계산한다(샘플에는 모드 시간이 없다).

설계 문서: `자료/대시보드-통합설계.html` (화면 11개 · 데이터 흐름 · 기록 · 코드 구조 · 시안과 달라진 점).
